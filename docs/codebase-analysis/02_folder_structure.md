# Folder Structure

This document outlines the folder structure of the Langratia Pharmacy POS application, detailing the purpose and responsibilities of each module.

## Root Directory (`/`)
- **`app.go`**: Core application controller. Defines the `App` struct, bindings for Wails, lifecycle hooks, and dependency injection for services.
- **`main.go`**: Application entry point. Configures the Wails application options (window size, asset server) and runs the application.
- **`wails.json`**: Wails project configuration (name, build scripts, packaging details).
- **`go.mod` / `go.sum`**: Go backend dependencies.
- **`package.json`**: Frontend dependency list (usually found inside `frontend/` but a proxy might exist at root in some setups).
- **`build/`**: Contains assets and configuration for OS-specific builds (e.g., Windows NSIS installer, macOS app bundle, icons).

---

## Backend (`/backend/`)
Contains all Go source code for business logic, data persistence, and network communication.

### `/backend/api/`
- **Purpose**: Facilitates HTTP RPC communication for the LAN Host/Client architecture.
- **Responsibilities**: Host the HTTP server (`server.go`) and handle incoming remote procedure calls by reflecting them to local `App` methods (`rpc.go`).
- **Dependencies**: Go `net/http`, `reflect`.

### `/backend/db/`
- **Purpose**: Database connection and schema management.
- **Responsibilities**: Initializing the SQLite database, providing DB connection instances, running migrations, and seeding initial data (`schema.go`, `seeder.go`).
- **Dependencies**: `github.com/mattn/go-sqlite3`.

### `/backend/logger/`
- **Purpose**: Application logging.
- **Responsibilities**: Write structured logs to local files (`logs/` directory) and standard output.

### `/backend/models/`
- **Purpose**: Data structures.
- **Responsibilities**: Define Go structs that map to database tables and are serialized to JSON for frontend communication (e.g., `User`, `Medicine`, `Sale`).

### `/backend/network/`
- **Purpose**: LAN discovery.
- **Responsibilities**: Provide UDP broadcast capabilities (`discovery.go`) so client terminals can automatically find the host terminal's IP and port.

### `/backend/services/`
- **Purpose**: Core business logic (The Service Layer).
- **Responsibilities**: Each file manages a specific domain (e.g., `auth_service.go`, `sales_service.go`, `inventory_service.go`). They interact with `backend/db/` to execute CRUD operations and enforce business rules.
- **Dependencies**: `backend/db/`, `backend/models/`.

---

## Frontend (`/frontend/`)
Contains the React SPA (Single Page Application) built with Vite and TypeScript.

### `/frontend/src/`
- **`App.tsx` & `main.tsx`**: React application entry point, routing setup, and global context providers.

### `/frontend/src/components/`
- **Purpose**: Reusable UI components.
- **Responsibilities**: UI elements (buttons, modals, tables, layouts) that do not contain heavy business logic.

### `/frontend/src/context/`
- **Purpose**: Global state management.
- **Responsibilities**: Provides application-wide state using React Context (e.g., `AuthContext`, `PermissionContext`, `ThemeContext`).

### `/frontend/src/features/`
- **Purpose**: Domain-specific UI modules.
- **Responsibilities**: Groups components, hooks, and logic by feature (e.g., `auth`, `pos`, `inventory`, `dashboard`). This modularizes the codebase for better maintainability.

### `/frontend/src/utils/`
- **Purpose**: Helper functions.
- **Responsibilities**: Contains formatting (currency, dates), calculations, and purely functional utilities.

### `/frontend/src/wailsjs/`
- **Purpose**: Wails IPC Bindings.
- **Responsibilities**: Auto-generated by the Wails CLI during build. Contains TypeScript definitions and functions to call the Go methods defined on the `App` struct. *Do not edit manually.*

### `/frontend/src/types/`
- **Purpose**: TypeScript definitions.
- **Responsibilities**: Define interfaces and types used across the frontend, often mirroring the Go models in `backend/models/`.
